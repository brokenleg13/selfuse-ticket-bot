# 新版 Interpark 自动化业务流程

## 主流程

启动卡片 → 商品入口 → 网站确认/排队 → 日期与场次 → 验证码 → 后台查询座位 → 筛选候选 → 预选并完成选择 → 按锁座数量选择票价 → 付款信息页停止。

每次启动有独立运行代次。停止后，旧代次的异步结果不得继续选座或点击完成。演出、场次改变时丢弃旧查询结果和座位缓存。

## 后台座位查询

1. 读取当前登录会话、演出、场次及区域列表，校验与卡片一致。
2. 区域配置为空：每轮覆盖全场区域；非空：只查询配置区域，保留配置顺序作为选座优先级。找不到区域时不擅自扩大范围。
3. 将区域分成每批最多 16 个的请求。批次内只发一次 `seatStatus`，传入完整 `blockKeys` 数组。
4. 缺少缓存、缓存超过 60 秒或元数据版本变化时，合并请求对应区域的 `seatMeta`。
5. 按 `blockKey` 对齐状态和元数据，不能依赖响应顺序。状态位图按座位列表顺序解析；批次缺区、位图损坏或长度不足时不返回候选。
6. 按区域优先级、排数限制、数量、同等级连续座位或完整座位组筛选。
7. 无候选则继续下一批；一轮完成后按刷新间隔开始下一轮。

批次间隔沿用 `areaScanIntervalMs`；轮次间隔沿用 `refreshIntervalMs` 和抖动。旧版 `maxAreaClicksPerRefresh` 不再控制新版查询范围。

**查询范围、请求时机和候选结果都不依赖地图缩放、可视区域、当前点击的区域或动画是否结束。** 网页自身也可能请求座位并更新地图，它与插件轮询是两套独立调用。

## 验证码与异常处理

| 情况 | 行为 |
|---|---|
| 页面有文字验证码 | 调用本地 `/ocr`，填入并提交，确认结果后继续 |
| 页面有拼图验证码 | 调用本地 `/slider`，验证通过后继续 |
| 查询返回 403 | 触发一次前台区域检查，检查是否弹验证码；这是异常处理，不是查询座位的前置条件 |
| 查询返回 401 | 停止，提示会话失效 |
| 查询返回 429 | 至少等待 30 秒；服务器要求更长时遵守 `Retry-After`，期间不点击地图 |
| 网络或服务错误 | 显示错误，按刷新间隔重试，不点击地图 |

前台检查结束后点击一次右下角恢复按钮，同一轮即可继续接口请求，不等待恢复动画。验证码仍存在时先处理验证码，不继续选座。

## 选座与完成

1. 提交前重新查询候选所在区域的状态。
2. 使用网站原生选座处理函数，确认网站会话记录已包含目标座位。
3. 使用组件结构定位“完成选择”按钮，不按翻译文案匹配。
4. 确认进入 `?step=price` 后继续票价流程。预选部分失败、完成跳转未确认或页面已有其他已选座位时停止，保留页面供检查。
5. 票价分组数量必须与已锁座位和配置张数一致。每组仅有一种票价时逐次增加数量，等待 React 确认；有多个票价选项时停止，不猜测优惠资格。
6. 按组内已锁数量确认完成，不把步进器的 `aria-valuemax` 当作目标总数：实页中它会变成剩余可增加数量，选满后为 0。
7. 数量就绪后只点击一次票价页继续按钮，进入 `/onestop/payment` 后停止。联系人、条款和付款不自动提交。

## 代码职责

| 函数/文件 | 职责 |
|---|---|
| `runOnestopLoop` / `runOnestopSeatTick` | 页面步骤和验证码/异常处理调度 |
| `validateOnestopContext` | 卡片与当前演出、场次校验 |
| `planOnestopBatches` | 区域范围、优先级、分批；无 DOM 操作 |
| `scanOnestopSeats` | 后台批次扫描与候选提交；不读取地图状态 |
| `onestop-main.js` 的 `pollBatch` | 复用页面请求客户端、缓存、位图解析；不操作地图 |
| `handleOnestopQueryFailure` | 错误分类、重试时间、受阻检查调度 |
| `recoverOnestopMap` | 仅处理受阻后的前台检查及恢复显示 |
| `selectOnestopSeats` | 原生预选、完成按钮、结果确认 |
| `advanceOnestopPrice` | 锁座与票价数量核对、计数、单次提交票价、等待跳转 |
